# SQLiteSyntax

Swift types for SQLite's SQL syntax, generated from SQLite's own language definition, with a parser that turns SQL text back into those types.

```swift
import SQLiteSyntax

let statement = try SQLStatement(parsing: "SELECT a, b FROM t WHERE a > 1 ORDER BY b DESC")
print(try statement.sql())          // SELECT a , b FROM t WHERE a > 1 ORDER BY b DESC

let expression = try Expression(parsing: "price * (1 + tax)")
```

## Building for a SQLite release

By default, the `.sql()` generation of an expression checks the validity of the the expression against the *currently linked* version of SQLite. If the expression contains syntax that is unsupported by the current SQLite version, a `SyntaxError.unsupported` error will be thrown. You may override this behavior by manually specifying a newer SQLite version, or by specifying `nil`:

```swift
let sql = try statement.sql()                                            // for the linked SQLite
let older = try statement.sql(sqliteVersion: SQLiteVersion(3, 31, 0))    // for another release
let unchecked = try statement.sql(sqliteVersion: nil)                    // no check
```

You may also ask an expression which SQLite version it needs to execute:
```swift
let requiredVersion = try SQLStatement(parsing: "DELETE FROM t RETURNING *").minimumRequiredVersion    // 3.35.0
```

SQLiteSyntax will also report about required or disallowed compilation options.

```swift
let sql1 = try SQLStatement(parsing: "PRAGMA foreign_keys").sql(options: [SQLiteOption(name: "OMIT_PRAGMA")])
// throws a .disallowedOption error, because `PRAGMA foreign_keys` will not execute if SQLite is compiled with `SQLITE_OMIT_PRAGMA`

let sql2 = try SQLStatement(parsing: "DELETE FROM t LIMIT 1 OFFSET 2").sql(options: [])
// throws a .requiredOption error, because deleting with a limit requires SQLite to be compiled with `SQLITE_ENABLE_UPDATE_DELETE_LIMIT`
```
## Deeply nested SQL

Parsing and building are recursive. Rather than overflow the thread's stack on deeply nested SQL, they stop and throw an error when less than 128 KB of stack is left. How deep they get depends on the thread on which building or parsing is run. If you're parsing SQL and find that you're consistently running out of stack space, consider parsing on a thread with a larger stack.

## Generated code

Everything in `Sources/SQLiteSyntax/Generated/` (including `Base/`, `Builder/` and `Parser/`) comes from the generator in a sibling package. Those files start with a `// Generated by sqlite-grammar` header. Do not edit them by hand, as any change will be over-written the next time the generator is run.

## Testing

```bash
swift test
```

To check agreement with SQLite on its own test suite (about 48,000 statements; see `CORPUS.md`), with a
SQLite source checkout at `../sqlite`:

```bash
SQLITE_CORPUS=1 swift test -c release --filter CorpusTests
```
