# SQLiteSyntax

Swift types for SQLite's SQL syntax, generated from SQLite's own language definition, plus a parser
that turns SQL text back into those types.

```swift
import SQLiteSyntax

let statement = try SQLStatement(parsing: "SELECT a, b FROM t WHERE a > 1 ORDER BY b DESC")
print(try statement.sql())          // SELECT a , b FROM t WHERE a > 1 ORDER BY b DESC

let expression = try Expression(parsing: "price * (1 + tax)")
```

## Building for a SQLite release

Pass the SQLite release you're targeting to get an error, not SQL that release can't parse:

```swift
import SQLite3

let running = SQLiteVersion(number: sqlite3_libversion_number())
let sql = try statement.sql(sqliteVersion: running)   // throws SyntaxError.unsupported if too new
```

The check covers the generated types: each type, case and optional part knows the release that introduced its
keywords (the doc comments say "Since SQLite x.y.z"). Without a release (`sql()`), nothing is checked.
Hand-written `Expression` syntax isn't checked yet, for example `->` and `IS DISTINCT FROM`. Syntax that
arrived without a new keyword is checked against the earlier release that introduced its keywords, or isn't
checked at all. See SQLiteSyntaxGenerator's README.

## Layout

One library, `SQLiteSyntax`:

| Folder | What it is |
|---|---|
| `Generated/` | The syntax types, produced by the generator. `Generated/Parsing/` holds their generated `parse(_:)` functions; every top-level type gets `init(parsing:)`. |
| `Core/` | Hand-written: expressions, literals, names, versions, and `SyntaxBuilder`. |
| `Convenience/` | Hand-written builder API and literal conformances. |
| `Parsing/` | Hand-written parsing: the tokenizer, the expression parser (precedence climbing), and the runtime the generated parsers use. |

The package has no dependencies. The library embeds SQLite's keyword and precedence tables, so it doesn't
need the SQLite library at runtime. The tests link the system SQLite to compare against it.

## Generated code

Everything in `Sources/SQLiteSyntax/Generated/` (including `Generated/Parsing/`) comes from the
generator in the sibling [`SQLiteSyntaxGenerator`](../SQLiteSyntaxGenerator) package. Those files start
with a `// Generated by sqlite-grammar` header. Don't edit them by hand: change the generator or its
`Grammar/codegen.json`, then regenerate. See that package's README for how to regenerate and how to move
a rule to a generated type.

## Testing

```bash
swift test
```

To check agreement with SQLite on its own test suite (about 48,000 statements; see `CORPUS.md`), with a
SQLite source checkout at `../sqlite`:

```bash
SQLITE_CORPUS=1 swift test -c release --filter CorpusTests
```
