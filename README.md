# SQLiteSyntax

Swift types for SQLite's SQL syntax, generated from SQLite's own language definition, plus a parser
that turns SQL text back into those types.

```swift
import SQLiteSyntax

let statement = try SQLStatement(parsing: "SELECT a, b FROM t WHERE a > 1 ORDER BY b DESC")
print(try statement.sql())          // SELECT a , b FROM t WHERE a > 1 ORDER BY b DESC

let expression = try Expression(parsing: "price * (1 + tax)")
```

## Building for a SQLite release

Building SQL checks that the SQLite release you're targeting can parse it, and throws
`SyntaxError.unsupported` if not. By default that's the SQLite this process links, `SQLiteVersion.linked`:

```swift
let sql = try statement.sql()                                            // for the linked SQLite
let older = try statement.sql(sqliteVersion: SQLiteVersion(3, 31, 0))   // for another release
let unchecked = try statement.sql(sqliteVersion: nil)                    // no check
```

Every syntax value also reports the earliest release that can run it, counting only the parts that are
present: `try SQLStatement(parsing: "DELETE FROM t RETURNING *").minimumRequiredVersion` is 3.35.0.

`SQLiteVersion.generatedAgainst` is the SQLite release the package was generated against (its source
checkout's `VERSION`). The parser knows syntax up to that release; syntax added later is rejected or
misread, so a linked SQLite newer than it may accept SQL the parser doesn't.

Each generated type, case and optional part knows the release that introduced it (the doc comments say
"Since SQLite x.y.z"): mostly worked out from when its keywords appeared, with hand-set dates where that
would be too early (`ROLLBACK TO`, `UPDATE … FROM`, the 3.52.0 `ALTER TABLE` constraint commands). The
hand-written expressions check theirs: `->`/`->>`, `IS [NOT] DISTINCT FROM`, `FILTER`. One gap: an alias on a table inside a trigger body needs 3.52.0 there, but
is checked as 3.24.0. See SQLiteSyntaxGenerator's README.

## Deeply nested SQL

Parsing and building are recursive. Rather than overflow the thread's stack on deeply nested SQL, they
stop when less than 128 KB of stack is left: parsing throws a `ParseError` ("SQL is nested too deeply to
parse") and building throws `SyntaxError.nestedTooDeeply`. How deep they get depends on the thread: on a
512 KB stack (Swift concurrency's threads), a release build handles about 570 nested parentheses or 100
nested subqueries, and a debug build about 38 and 16. The main thread's 8 MB stack allows about 16 times
as much. To handle deeper SQL, parse on a thread with a larger stack.

## Layout

One library, `SQLiteSyntax`:

| Folder | What it is |
|---|---|
| `Generated/` | Produced by the generator, three files per type: `Base/X.swift` (the type), `Builder/X+Builder.swift` (its `build(using:)`) and `Parser/X+Parser.swift` (its `parse(_:)`, which `Syntax` requires; every `Syntax` type gets `init(parsing:)` from it). |
| `Core/` | Hand-written: expressions, literals, names, versions, and `SyntaxBuilder`. |
| `Convenience/` | Hand-written builder API and literal conformances. |
| `Parsing/` | Hand-written parsing: the tokenizer, the expression parser (precedence climbing), and the runtime the generated parsers use. |

The package has no package dependencies. The library embeds SQLite's keyword and precedence tables, and
links the system SQLite only for `SQLiteVersion.linked`. The tests also use it to compare against SQLite.

## Generated code

Everything in `Sources/SQLiteSyntax/Generated/` (including `Base/`, `Builder/` and `Parser/`) comes from the
generator in the sibling [`SQLiteSyntaxGenerator`](../SQLiteSyntaxGenerator) package. Those files start
with a `// Generated by sqlite-grammar` header. Don't edit them by hand: change the generator or its
`Grammar/codegen.json`, then regenerate. See that package's README for how to regenerate and how to move
a rule to a generated type.

## Testing

```bash
swift test
```

To check agreement with SQLite on its own test suite (about 48,000 statements; see `CORPUS.md`), with a
SQLite source checkout at `../sqlite`:

```bash
SQLITE_CORPUS=1 swift test -c release --filter CorpusTests
```
